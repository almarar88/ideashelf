# إعداد المزامنة والحساب (Supabase)

التطبيق يعمل **بالكامل دون إنترنت** إن لم تُضبط هذه الإعدادات: شاشة الحساب تظهر رسالة
«المزامنة غير مفعّلة في هذه النسخة» ويبقى كل شيء محلياً. الخطوات التالية تفعّل تسجيل
الدخول ومزامنة المهام بين الأجهزة.

المدة المتوقعة: ١٥ دقيقة. لا حاجة إلى بطاقة ائتمان — الخطة المجانية تكفي لبداية النشر.

---

## ١. أنشئ مشروعاً على Supabase

1. افتح <https://supabase.com> ← **Start your project** ← سجّل بحساب GitHub أو بريدك.
2. **New project**:
   - **Name**: `mahami`
   - **Database Password**: ولّد كلمة قوية واحفظها في مدير كلمات المرور (لن تحتاجها في التطبيق).
   - **Region**: اختر الأقرب لمستخدميك — `Middle East (Bahrain)` أو `Europe (Frankfurt)`.
3. انتظر حتى ينتهي التجهيز (دقيقتان تقريباً).

## ٢. أنشئ الجداول والسياسات

1. من القائمة الجانبية: **SQL Editor** ← **New query**.
2. انسخ محتوى `supabase/schema.sql` كاملاً والصقه، ثم **Run**.
3. تأكد من ظهور `Success. No rows returned`.

ماذا أنشأ هذا الملف؟

| العنصر | الغرض |
|---|---|
| جدول `records` | يحمل المهام والمشاريع كحمولة JSON مع `sync_id` و`updated_at` |
| قيد `records_user_sync_unique` | يجعل الرفع `upsert` بدل التكرار |
| سياسات RLS الأربع | كل مستخدم يقرأ ويكتب سجلاته فقط — لا يمكن لأحد رؤية بيانات غيره |
| زناد `touch_updated_at` | يحدّث الطابع الزمني تلقائياً ليعمل حل التعارض «الأحدث يفوز» |
| دالة `delete_account()` | حذف الحساب وكل بياناته — **متطلب إلزامي في Google Play** |

## ٣. اضبط المصادقة

من **Authentication** ← **Providers** ← **Email**:

- **Enable Email provider**: مفعّل.
- **Confirm email**: مفعّل (موصى به). عندها يُرسل Supabase رسالة تأكيد ويعرض التطبيق
  «أرسلنا رسالة تأكيد إلى بريدك».
  إن عطّلته يدخل المستخدم مباشرة بعد التسجيل — أسهل للتجربة، أضعف أمنياً.
- **Minimum password length**: `6` (التطبيق يفرض ٦ أحرف في الواجهة).

> رسائل Supabase المجانية محدودة العدد وقد تصل إلى مجلد البريد المزعج. لنشرٍ جادّ
> اضبط **SMTP** خاصاً بك من **Project Settings → Auth → SMTP Settings**.

## ٤. انسخ المفتاحين

من **Project Settings** ← **API**:

- **Project URL** — مثل `https://abcdefghijklm.supabase.co`
- **anon public** — مفتاح طويل يبدأ بـ `eyJ...`

> `anon` مفتاح عام مصمّم ليوضع داخل التطبيق؛ سياسات RLS هي ما يحمي البيانات.
> **لا تضع `service_role` في التطبيق إطلاقاً** — فهو يتجاوز كل السياسات.

## ٥. أدخلهما في البناء

أضفهما إلى `~/.gradle/gradle.properties` (خارج المستودع، فلا يُرفعان أبداً):

```properties
SUPABASE_URL=https://abcdefghijklm.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

ثم ابنِ كالمعتاد:

```bash
gradle :app:bundleRelease
```

إن بنيت بدونهما فالتطبيق يعمل محلياً ولا شيء ينكسر.

### في GitHub Actions

أضف السرّين في **Settings → Secrets and variables → Actions**، ثم مرّرهما:

```yaml
- run: gradle :app:bundleRelease
  env:
    ORG_GRADLE_PROJECT_SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
    ORG_GRADLE_PROJECT_SUPABASE_ANON_KEY: ${{ secrets.SUPABASE_ANON_KEY }}
```

## ٦. الإدخال اليدوي للتجربة

للتجربة السريعة دون إعادة بناء: **الإعدادات ← الحساب والمزامنة ← خادم المزامنة ← إعداد**،
ألصق الرابط والمفتاح واحفظ. يُخزَّنان في DataStore الخاص بالتطبيق ويتجاوزان قيم البناء.

## كيف تعمل المزامنة

| الخطوة | ما يحدث |
|---|---|
| **الرفع** | كل مهمة ومشروع تغيّرا محلياً يُرسلان إلى `/rest/v1/records?on_conflict=user_id,sync_id` مع `Prefer: resolution=merge-duplicates` |
| **التنزيل** | تُجلب السجلات الأحدث من آخر مزامنة، المشاريع أولاً ثم المهام لتُربط بمشاريعها |
| **التعارض** | الأحدث يفوز حسب `updated_at` — لا يُفقد أي تعديل صامتاً |
| **الحذف** | يُسجَّل «شاهد قبر» (tombstone) ويُرفع كسجل `deleted = true` فيختفي من الأجهزة الأخرى |
| **دون إنترنت** | كل شيء يُحفظ محلياً في Room؛ المزامنة تُستأنف تلقائياً عند فتح التطبيق متصلاً |

كل مهمة تحمل `syncId` (UUID) يُولَّد عند الإنشاء، فلا تتكرر المهام عند المزامنة من جهازين.

## متطلبات Google Play المتعلقة بالحساب

- **حذف الحساب**: مسار داخل التطبيق (الحساب ← حذف الحساب نهائياً) يستدعي `delete_account()`.
  ستحتاج أيضاً إلى رابط ويب لحذف الحساب في نموذج **Data safety** — استخدم صفحة الخصوصية.
- **Data safety**: صرّح بجمع **البريد الإلكتروني** و**بيانات التطبيق (المهام)**،
  وأنها **تُنقل مشفّرة** (HTTPS) و**يمكن حذفها**.
- **سياسة الخصوصية**: يجب أن تذكر Supabase كمعالج بيانات ومكان تخزينها (المنطقة التي اخترتها).

## استكشاف الأخطاء

| الرسالة | السبب والحل |
|---|---|
| «المزامنة غير مفعّلة في هذه النسخة» | لم يُضبط `SUPABASE_URL` أو `SUPABASE_ANON_KEY` |
| «بيانات الدخول غير صحيحة» | كلمة مرور خاطئة، أو البريد لم يُفعّل بعد |
| «فعّل بريدك أولاً» | افتح رسالة التأكيد، أو عطّل **Confirm email** للتجربة |
| المزامنة تنجح ولا تظهر البيانات | تحقق أن `schema.sql` نُفّذ كاملاً وأن RLS مفعّل على `records` |
| خطأ عند حذف الحساب | تأكد من وجود `delete_account()` وأن `grant execute ... to authenticated` نُفّذ |
